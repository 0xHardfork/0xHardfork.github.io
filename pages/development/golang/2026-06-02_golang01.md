# Golang

## 🧠 Concept Overview

Go's approach to I/O is built around two of the most elegant and powerful abstractions in its standard library: `io.Reader` and `io.Writer`. These two interfaces are so pervasive that once you truly understand them, you'll see them everywhere — in HTTP request bodies, file handles, network connections, compression streams, cryptographic hashers, and even in-memory buffers. Before we go there, though, let's understand *why* Go designed I/O this way.

### The `io.Reader` and `io.Writer` Philosophy

In languages like Java or C#, I/O tends to be class-hierarchy-heavy. You have `InputStream`, `BufferedInputStream`, `FileInputStream`, etc. — a deep tree of concrete classes. Go throws all of that out and replaces it with two ultra-minimal interfaces:

```go
type Reader interface {
    Read(p []byte) bool// wrong — here's the real one:
    Read(p []byte) (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}
```

That's it. Just one method each. The beauty of this minimalism is that **anything** can be an `io.Reader` — a file, a network socket, a gzip stream, an in-memory byte slice, a cryptographic hasher, or even a random-number generator. The same `io.Copy`, `json.NewDecoder`, `bufio.Scanner`, etc. work uniformly across all of them.

This design philosophy — "program to interfaces, not implementations" — is the beating heart of idiomatic Go. Go's standard library is a masterclass in this.

### `io.Reader` in Depth

The `Read` method fills the provided buffer `p []byte` with up to `len(p)` bytes and returns the number of bytes actually read (`n`) plus any error. There are three critical behaviours you *must* internalize:

1. **`n > 0, err == nil`** — Successfully read `n` bytes, and more data may follow.
2. **`n > 0, err == io.EOF`** — Read the last `n` bytes; stream is exhausted. This is a *valid, non-error* condition. **You must process those `n` bytes before checking the error.**
3. **`n == 0, err == io.EOF`** — Stream is completely exhausted; no new bytes were read. This is the loop-termination signal.
4. **`n == 0, err != nil && err != io.EOF`** — A real error occurred (network reset, disk error, etc.).

The single most common beginner mistake in Go I/O is writing:

```go
// WRONG: discards the last chunk of data!
for {
    n, err := r.Read(buf)
    if err != nil { // breaks BEFORE processing when err == io.EOF with n > 0
        break
    }
    process(buf[:n])
}
```

The correct pattern is:

```go
// CORRECT: always process n bytes first, then handle error
for {
    n, err := r.Read(buf)
    if n > 0 {
        process(buf[:n]) // always handle data first
    }
    if err == io.EOF {
        break
    }
    if err != nil {
        log.Fatal(err)
    }
}
```

### `io.Writer` in Depth

`Write` sends `len(p)` bytes from `p` to the underlying data stream. It must return a non-nil error if `n < len(p)`. This guarantee means that if `Write` returns `err == nil`, you know all bytes were written. This is different from C's `write()` syscall, which can write fewer bytes on EINTR.

### The `io` Package — The Swiss Army Knife

The `io` package bundles a collection of utilities built entirely on top of `Reader` and `Writer`. These are the ones you'll use daily:

| Function / Type | What it does |
|---|---|
| `io.Copy(dst Writer, src Reader)` | Streams src → dst without loading into memory. Crucial for large files. |
| `io.ReadAll(r Reader)` | Reads everything into a `[]byte`. Use carefully on large streams. |
| `io.LimitReader(r, n)` | Wraps a Reader to read at most `n` bytes. Great for security (prevent zip bombs). |
| `io.TeeReader(r, w)` | Reads from `r`, simultaneously writes to `w`. Like `tee` in Unix pipes. |
| `io.MultiWriter(w1, w2, ...)` | Fans out writes to multiple writers at once. |
| `io.MultiReader(r1, r2, ...)` | Chains multiple readers into one logical stream. |
| `io.Pipe()` | Creates an in-memory synchronous pipe (`PipeReader`, `PipeWriter`). |
| `io.Discard` | A writer that discards all data (like `/dev/null`). |

### `bufio` — The Performance Layer

Raw `io.Reader` and `io.Writer` do syscalls on every single `Read`/`Write`. This is catastrophically slow for small reads (e.g., reading a file character by character). `bufio` wraps any Reader/Writer with an in-memory buffer, batching syscalls dramatically:

```go
f, _ := os.Open("data.txt")
scanner := bufio.NewScanner(f)
for scanner.Scan() {
    line := scanner.Text() // one line at a time, buffered
}
```

`bufio.Scanner` has a default buffer of 64KB. If you're scanning lines longer than 64KB (e.g., minified JSON), you need to expand it:

```go
scanner := bufio.NewScanner(f)
buf := make([]byte, 1024*1024) // 1MB buffer
scanner.Buffer(buf, len(buf))
```

`bufio.Writer` buffers writes and only flushes to the underlying writer when the buffer fills or you call `Flush()`. **Always call `Flush()` when done writing**, otherwise the last chunk of data may be silently lost:

```go
w := bufio.NewWriter(f)
w.WriteString("hello world\n")
w.Flush() // MUST do this!
```

### `os` Package — File I/O

Go's `os` package provides file operations. The key types are `os.File` (which implements both `io.Reader` and `io.Writer`):

```go
// Reading a file
f, err := os.Open("input.txt")       // Read-only
f, err := os.OpenFile("log.txt", os.O_WRONLY|os.O_CREATE|os.O_APPEND, 0644) // Fine-grained control

// Writing a whole file at once
os.WriteFile("output.txt", []byte("data"), 0644)

// Reading a whole file at once
data, err := os.ReadFile("input.txt")
```

The `defer f.Close()` pattern is idiomatic Go — always defer the close right after opening:

```go
f, err := os.Open("file.txt")
if err != nil {
    return err
}
defer f.Close() // guaranteed to run when function exits
```

### JSON Encoding & Decoding (encoding/json)

Go's `encoding/json` package is one of the most used in the entire ecosystem. It uses Go's reflection system to automatically serialize/deserialize structs based on their field names and struct tags.

#### Struct Tags — The Control Plane

Struct tags are string literals in backticks attached to struct fields. The `encoding/json` package reads them to determine:
- The JSON key name for a field
- Whether to omit the field when it's empty
- Whether to skip the field entirely

```go
type User struct {
    ID        int    `json:"id"`
    Name      string `json:"name"`
    Email     string `json:"email,omitempty"` // omitted if ""
    Password  string `json:"-"`               // ALWAYS omitted (security!)
    CreatedAt time.Time `json:"created_at"`
}
```

Key rules:
- **`json:"name"`** — Use `name` as the JSON key (instead of `Name`)
- **`json:"name,omitempty"`** — Omit the field if it's the zero value (`""`, `0`, `false`, `nil`, empty slice)
- **`json:"-"`** — Always exclude this field (great for passwords, internal state)
- **No tag** — The field name is used as-is (exported fields only; unexported fields are always ignored)

#### `json.Marshal` vs `json.NewEncoder` — Which to Use?

```go
// Marshal: encode to []byte — good for small payloads in memory
data, err := json.Marshal(user)

// NewEncoder: stream directly to a Writer — good for HTTP responses, files
enc := json.NewEncoder(w) // w is an io.Writer
enc.SetIndent("", "  ")   // pretty print
err := enc.Encode(user)   // writes JSON + newline to w
```

Rule of thumb: **Use `json.NewEncoder` when writing to HTTP responses or files. Use `json.Marshal` when you need the `[]byte` in memory.**

#### `json.Unmarshal` vs `json.NewDecoder`

```go
// Unmarshal: decode from []byte
var user User
err := json.Unmarshal(data, &user) // note: pointer!

// NewDecoder: stream from a Reader — perfect for HTTP request bodies
dec := json.NewDecoder(r.Body)
dec.DisallowUnknownFields() // reject unknown JSON keys (strict mode)
var req CreateUserRequest
err := dec.Decode(&req)
```

#### Handling Dynamic / Unknown JSON — `map` and `json.RawMessage`

Sometimes you don't know the structure at compile time:

```go
// Use map[string]interface{} for fully dynamic JSON
var result map[string]interface{}
json.Unmarshal(data, &result)
name := result["name"].(string) // type assertion — panics if wrong type!

// Safer: use map[string]json.RawMessage to defer decoding
var raw map[string]json.RawMessage
json.Unmarshal(data, &raw)
var name string
json.Unmarshal(raw["name"], &name) // decode only the fields you need
```

#### Custom Marshaling — `json.Marshaler` / `json.Unmarshaler`

Implement these interfaces for types that need custom JSON representation:

```go
type Duration time.Duration

func (d Duration) MarshalJSON() ([]byte, error) {
    return json.Marshal(time.Duration(d).String()) // "1h30m"
}

func (d *Duration) UnmarshalJSON(data []byte) error {
    var s string
    if err := json.Unmarshal(data, &s); err != nil {
        return err
    }
    dur, err := time.ParseDuration(s)
    *d = Duration(dur)
    return err
}
```

### Go Testing — `testing` Package

Go has testing built into the language toolchain — no third-party framework required. Tests live in `_test.go` files alongside the source code.

#### Basic Test Structure

```go
// math_test.go
package math_test // or package math (whitebox testing)

import (
    "testing"
    "your/package/math"
)

func TestAdd(t *testing.T) {
    result := math.Add(2, 3)
    if result != 5 {
        t.Errorf("Add(2,3) = %d; want 5", result)
    }
}
```

Run tests with:
```bash
go test ./...           # run all tests in all packages
go test -v ./...        # verbose output (see test names)
go test -run TestAdd    # run only tests matching the regex
go test -count=1 ./...  # disable test caching (always re-run)
go test -race ./...     # enable the race detector (ALWAYS USE IN CI!)
```

#### `*testing.T` — The Core API

| Method | Purpose |
|---|---|
| `t.Errorf(format, args...)` | Log a failure but **continue** the test |
| `t.Fatalf(format, args...)` | Log a failure and **stop** the test immediately |
| `t.Logf(format, args...)` | Log a message (only printed on failure unless `-v`) |
| `t.Run(name, func)` | Create a subtest (enables parallel subtests) |
| `t.Parallel()` | Mark this test to run in parallel with other parallel tests |
| `t.Helper()` | Mark current function as a test helper (affects error line reporting) |
| `t.Cleanup(func)` | Register a cleanup function (like `defer` but scoped to the test) |
| `t.Skip(msg)` | Skip this test with a message |

#### Table-Driven Tests — The Idiomatic Go Pattern

This is the single most important testing pattern in Go. Instead of writing one test per case, you define a slice of test cases and loop over them:

```go
func TestAdd(t *testing.T) {
    tests := []struct {
        name     string
        a, b     int
        expected int
    }{
        {"positive + positive", 2, 3, 5},
        {"negative + positive", -1, 1, 0},
        {"negative + negative", -2, -3, -5},
        {"zero + zero", 0, 0, 0},
        {"overflow edge case", math.MaxInt, 1, math.MinInt},
    }

    for _, tc := range tests {
        tc := tc // capture range variable! (pre-Go 1.22 fix)
        t.Run(tc.name, func(t *testing.T) {
            t.Parallel() // run subtests in parallel
            result := Add(tc.a, tc.b)
            if result != tc.expected {
                t.Errorf("Add(%d, %d) = %d; want %d", tc.a, tc.b, result, tc.expected)
            }
        })
    }
}
```

> **Note on Go 1.22+**: The loop variable capture bug (`tc := tc`) is fixed automatically in Go 1.22 and later. The compiler now creates a new variable per iteration. But it's still good practice to write it explicitly for clarity and backwards compatibility.

#### Benchmarks

Benchmarks use `*testing.B` and are run with `go test -bench=.`:

```go
func BenchmarkAdd(b *testing.B) {
    for i := 0; i < b.N; i++ { // b.N is set by the framework
        Add(100, 200)
    }
}
```

```bash
go test -bench=. -benchmem ./...   # run benchmarks + show memory allocations
go test -bench=BenchmarkAdd -benchtime=5s  # run for 5 seconds
```

#### Testify — The De Facto Assertion Library

While the standard `testing` package has no built-in assertions, the `testify` library is widely used:

```go
import "github.com/stretchr/testify/assert"
import "github.com/stretchr/testify/require"

func TestSomething(t *testing.T) {
    result, err := DoSomething()
    require.NoError(t, err)          // Fatal: stops test on failure
    assert.Equal(t, "expected", result) // Non-fatal: continues on failure
    assert.Contains(t, result, "sub")
    assert.Nil(t, somePointer)
}
```

`require` vs `assert`: Use `require` when subsequent test code depends on the assertion passing (e.g., after a `NoError` check). Use `assert` for independent checks.

#### Test Helpers & `t.Helper()`

```go
func assertNoError(t *testing.T, err error) {
    t.Helper() // makes error lines point to the CALLER, not this function
    if err != nil {
        t.Fatalf("unexpected error: %v", err)
    }
}
```

Without `t.Helper()`, error messages point to the line inside `assertNoError`, which is useless. With it, they point to where `assertNoError` was called.

#### Mocking with Interfaces

Go's interface system makes mocking trivially easy — no reflection needed. Just define an interface and provide a test implementation:

```go
// Production code
type EmailSender interface {
    Send(to, subject, body string) error
}

type UserService struct {
    email EmailSender
}

// Test code
type mockEmailSender struct {
    sentEmails []string
}

func (m *mockEmailSender) Send(to, subject, body string) error {
    m.sentEmails = append(m.sentEmails, to)
    return nil
}

func TestUserService_Register(t *testing.T) {
    mock := &mockEmailSender{}
    svc := &UserService{email: mock}
    svc.Register("user@example.com")
    assert.Contains(t, mock.sentEmails, "user@example.com")
}
```

## 🔑 Key Points

- `io.Reader` and `io.Writer` are the backbone of all I/O in Go — master these two interfaces and the whole ecosystem opens up.
- Always process `n` bytes returned by `Read` **before** checking for `io.EOF` — the last read can return both data and `io.EOF` simultaneously.
- Use `json.NewEncoder(w)` / `json.NewDecoder(r)` for streaming I/O (HTTP, files); use `json.Marshal` / `json.Unmarshal` only when you need `[]byte` in memory.
- Struct tags (`json:"name,omitempty"`, `json:"-"`) give you full control over JSON serialization without writing a single line of custom code.
- Table-driven tests with `t.Run` subtests are the idiomatic Go testing pattern — they make test cases self-documenting and allow parallelism with `t.Parallel()`.
- Always run `go test -race` in CI to catch data races — the race detector has near-zero false-positive rate and catches real bugs.

## 💻 Code Examples

### Example 1 — Streaming File Processing with `io.Reader` / `io.Writer`

```go
// File: stream_copy.go
package main

import (
	"bufio"
	"compress/gzip"
	"fmt"
	"io"
	"os"
	"strings"
)

// countWords counts words in any io.Reader — works for files, HTTP bodies, strings, etc.
func countWords(r io.Reader) (int, error) {
	count := 0
	scanner := bufio.NewScanner(r)
	scanner.Split(bufio.ScanWords) // split by words, not lines
	for scanner.Scan() {
		count++
	}
	return count, scanner.Err()
}

// compressToGzip reads from src and writes gzip-compressed data to dst.
// Neither src nor dst need to be files — they just need to be Reader/Writer.
func compressToGzip(dst io.Writer, src io.Reader) error {
	gz := gzip.NewWriter(dst)
	defer gz.Close() // IMPORTANT: Close flushes the gzip footer

	_, err := io.Copy(gz, src)
	return err
}

// TeeReader example: read data while simultaneously hashing it
func main() {
	// --- Example 1: countWords works with any Reader ---
	text := "The quick brown fox jumps over the lazy dog"
	n, _ := countWords(strings.NewReader(text))
	fmt.Printf("Word count: %d\n", n) // 9

	// --- Example 2: Compress a string to a file ---
	outFile, err := os.Create("output.gz")
	if err != nil {
		fmt.Println("Error creating file:", err)
		return
	}
	defer outFile.Close()

	src := strings.NewReader("This is the content to compress. " + strings.Repeat("Go is awesome! ", 100))
	if err := compressToGzip(outFile, src); err != nil {
		fmt.Println("Compress error:", err)
		return
	}
	fmt.Println("Wrote output.gz")

	// --- Example 3: TeeReader — read + write simultaneously ---
	// Use case: stream HTTP response body to disk while also parsing headers
	var buf strings.Builder
	original := strings.NewReader("streaming data that we read once but log twice")
	tee := io.TeeReader(original, &buf) // everything read from tee is also written to buf

	data, _ := io.ReadAll(tee)
	fmt.Printf("Read:   %q\n", data)
	fmt.Printf("Copied: %q\n", buf.String()) // identical!

	// --- Example 4: LimitReader prevents reading too much data (security) ---
	huge := strings.NewReader(strings.Repeat("A", 10_000_000)) // 10MB source
	limited := io.LimitReader(huge, 1024)                        // only allow 1KB
	small, _ := io.ReadAll(limited)
	fmt.Printf("Read %d bytes (limit was 1024)\n", len(small))
}
```

**What this demonstrates**: How to chain `io.Reader`/`io.Writer` implementations together to build composable streaming pipelines without loading data into memory.

### Example 2 — JSON Encoding/Decoding with Struct Tags and Custom Types

```go
// File: json_serde.go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"log"
	"time"
)

// Duration is a custom type that serializes as a human-readable string ("1h30m")
// instead of Go's default nanosecond int64.
type Duration time.Duration

func (d Duration) MarshalJSON() ([]byte, error) {
	return json.Marshal(time.Duration(d).String())
}

func (d *Duration) UnmarshalJSON(data []byte) error {
	var s string
	if err := json.Unmarshal(data, &s); err != nil {
		return fmt.Errorf("duration: expected string, got %s", data)
	}
	dur, err := time.ParseDuration(s)
	if err != nil {
		return fmt.Errorf("duration: invalid format %q: %w", s, err)
	}
	*d = Duration(dur)
	return nil
}

type APIResponse struct {
	ID          int            `json:"id"`
	Name        string         `json:"name"`
	Score       float64        `json:"score,omitempty"` // omitted if 0.0
	Tags        []string       `json:"tags,omitempty"`  // omitted if nil/empty
	Password    string         `json:"-"`               // NEVER serialized
	ProcessTime Duration       `json:"process_time"`
	Metadata    map[string]any `json:"metadata,omitempty"`
}

func main() {
	original := APIResponse{
		ID:          42,
		Name:        "Blockchain Analyzer",
		Score:       0.0,           // will be omitted!
		Tags:        []string{},    // will be omitted! (empty slice)
		Password:    "secret123",   // will NEVER appear in JSON
		ProcessTime: Duration(90 * time.Minute),
		Metadata: map[string]any{
			"version": "1.2.3",
			"env":     "production",
		},
	}

	// --- Marshal to pretty JSON ---
	var buf bytes.Buffer
	enc := json.NewEncoder(&buf)
	enc.SetIndent("", "  ")
	if err := enc.Encode(original); err != nil {
		log.Fatal(err)
	}
	fmt.Println("Serialized JSON:")
	fmt.Println(buf.String())

	// --- Unmarshal back ---
	jsonStr := `{
		"id": 99,
		"name": "Test Item",
		"score": 9.5,
		"tags": ["go", "security"],
		"password": "this_is_ignored",
		"process_time": "2h15m",
		"metadata": {"region": "ap-northeast-1"}
	}`

	var decoded APIResponse
	dec := json.NewDecoder(bytes.NewBufferString(jsonStr))
	dec.DisallowUnknownFields() // strict: reject unexpected JSON keys
	if err := dec.Decode(&decoded); err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Decoded: ID=%d, Name=%q, Score=%.1f, ProcessTime=%s, Password=%q\n",
		decoded.ID, decoded.Name, decoded.Score,
		time.Duration(decoded.ProcessTime), decoded.Password) // Password is ""
}
```

**What this demonstrates**: Full lifecycle of JSON serialization — struct tags to control field names and omission, `json:"-"` for security-critical fields, custom `MarshalJSON`/`UnmarshalJSON` for bespoke types, streaming encoder/decoder, and `DisallowUnknownFields` for strict parsing.

### Example 3 — Table-Driven Tests with Subtests, Parallelism & Race Detector

```go
// File: parser_test.go
package parser_test

import (
	"errors"
	"testing"
)

// --- Code under test (normally in parser.go) ---
type Token struct {
	Type  string
	Value string
}

var ErrEmptyInput = errors.New("empty input")
var ErrInvalidChar = errors.New("invalid character")

func Tokenize(input string) ([]Token, error) {
	if input == "" {
		return nil, ErrEmptyInput
	}
	tokens := []Token{}
	for _, ch := range input {
		switch {
		case ch >= 'a' && ch <= 'z' || ch >= 'A' && ch <= 'Z':
			tokens = append(tokens, Token{Type: "IDENT", Value: string(ch)})
		case ch >= '0' && ch <= '9':
			tokens = append(tokens, Token{Type: "NUM", Value: string(ch)})
		case ch == ' ':
			// skip whitespace
		default:
			return nil, fmt.Errorf("%w: %q", ErrInvalidChar, ch)
		}
	}
	return tokens, nil
}

// --- Tests ---
func TestTokenize(t *testing.T) {
	tests := []struct {
		name        string
		input       string
		wantLen     int
		wantErr     error
		wantFirst   Token
	}{
		{
			name:      "simple identifier",
			input:     "abc",
			wantLen:   3,
			wantFirst: Token{Type: "IDENT", Value: "a"},
		},
		{
			name:    "empty string",
			input:   "",
			wantErr: ErrEmptyInput,
		},
		{
			name:    "invalid character",
			input:   "hello!",
			wantErr: ErrInvalidChar,
		},
		{
			name:      "mixed alphanumeric",
			input:     "a1 b2",
			wantLen:   4,
			wantFirst: Token{Type: "IDENT", Value: "a"},
		},
	}

	for _, tc := range tests {
		tc := tc // capture (pre-Go 1.22)
		t.Run(tc.name, func(t *testing.T) {
			t.Parallel() // run subtests concurrently

			got, err := Tokenize(tc.input)

			// Error assertions
			if tc.wantErr != nil {
				if !errors.Is(err, tc.wantErr) {
					t.Errorf("Tokenize(%q) error = %v; want %v", tc.input, err, tc.wantErr)
				}
				return // no further checks needed
			}
			if err != nil {
				t.Fatalf("Tokenize(%q) unexpected error: %v", tc.input, err)
			}

			// Length check
			if len(got) != tc.wantLen {
				t.Errorf("len(tokens) = %d; want %d", len(got), tc.wantLen)
			}

			// First token check
			if len(got) > 0 && got[0] != tc.wantFirst {
				t.Errorf("first token = %+v; want %+v", got[0], tc.wantFirst)
			}
		})
	}
}

// Benchmark
func BenchmarkTokenize(b *testing.B) {
	input := "hello world foo bar baz 123 abc"
	b.ResetTimer() // don't count setup time
	for i := 0; i < b.N; i++ {
		Tokenize(input)
	}
}
```

**What this demonstrates**: Full idiomatic table-driven test with parallel subtests, proper error wrapping (`errors.Is`), use of `t.Fatalf` vs `t.Errorf`, and a benchmark.

## ⚠️ Common Mistakes

| Mistake | Why it's wrong | Correct approach |
|---|---|---|
| Checking `err != nil` before processing `n` bytes in `Read` | When `err == io.EOF`, `n` may still be > 0 (last chunk of data is lost) | Always process `n` bytes first: `if n > 0 { process(buf[:n]) }; if err == io.EOF { break }` |
| Forgetting `bufio.Writer.Flush()` | Buffered data stays in memory and never reaches the underlying writer | Always `defer w.Flush()` or call `Flush()` when done |
| Using `json.Marshal` for HTTP response bodies | Encodes to `[]byte` then writes — double memory allocation | Use `json.NewEncoder(w).Encode(v)` to stream directly |
| Forgetting `json:"-"` on sensitive fields | Passwords, tokens, secrets get silently included in API responses | Always tag sensitive fields with `json:"-"` |
| Using `t.Fatal` in a helper function without `t.Helper()` | Error messages point to the helper function, not the test callsite | Call `t.Helper()` at the top of every test helper function |
| Not running `go test -race` | Data races are invisible without the race detector | Always run with `-race` in CI/CD pipelines |
| `tc := tc` missing in pre-1.22 parallel subtests | Loop variable captured by reference — all subtests see the last value | Add `tc := tc` before `t.Run` (fixed automatically in Go 1.22+) |

## 🏋️ Practice Exercises

### Exercise 1 — Word Frequency Counter (Easy)

**Goal**: Write a function that takes an `io.Reader` and returns a `map[string]int` of word frequencies.

**Requirements**:
- Use `bufio.Scanner` with `bufio.ScanWords` to tokenize
- Convert all words to lowercase before counting

### Exercise 8 — Concurrent Log Aggregator with Race Detection (Challenge!)

**Goal**: Build a concurrent log aggregator that spawns N goroutines, each streaming log entries into a central aggregator, which collects stats safely and produces a JSON report.

**Requirements**:
- Spawn 5 goroutines, each generating 1000 random log entries (`DEBUG`/`INFO`/`WARN`/`ERROR`)
- Use a channel `chan LogEntry` to stream entries to the aggregator goroutine
- The aggregator collects `map[string]int` counts — NO mutex needed (single aggregator goroutine owns the map)
- When all producers finish (use `sync.WaitGroup`), close the channel to signal the aggregator
- The aggregator goroutine writes the final `map[string]int` as JSON to an `io.Writer`
- Write a test that runs this with `-race` flag and verifies the final counts equal `5 * 1000 = 5000`

**Starter code**:

```go
package main

import (
    "encoding/json"
    "fmt"
    "io"
    "math/rand"
    "os"
    "sync"
)

type LogEntry struct {
    Level   string
    Message string
}

func producer(id int, ch chan<- LogEntry, wg *sync.WaitGroup) {
    defer wg.Done()
    levels := []string{"DEBUG", "INFO", "WARN", "ERROR"}
    for i := 0; i < 1000; i++ {
        ch <- LogEntry{
            Level:   levels[rand.Intn(len(levels))],
            Message: fmt.Sprintf("worker %d event %d", id, i),
        }
    }
}

func aggregator(ch <-chan LogEntry, w io.Writer) {
    // TODO: collect counts from channel, then write JSON report
}

func main() {
    ch := make(chan LogEntry, 100)
    var wg sync.WaitGroup

    for i := 0; i < 5; i++ {
        wg.Add(1)
        go producer(i, ch, &wg)
    }

    go func() {
        wg.Wait()
        close(ch)
    }()

    aggregator(ch, os.Stdout)
}
```

**Hint**: The aggregator simply `range ch` — it receives until the channel is closed. No mutex is needed because only the aggregator goroutine reads/writes the map. This is the "single owner" concurrency pattern.

## 🗒️ Quick Cheat Sheet

```go
// ── I/O ────────────────────────────────────────────────────────────────────
io.Copy(dst, src)                    // stream src → dst (no memory load)
io.ReadAll(r)                        // read all into []byte
io.LimitReader(r, n)                 // cap reads at n bytes
io.TeeReader(r, w)                   // read + simultaneously write to w
io.MultiWriter(w1, w2)              // fan-out writes to multiple destinations
io.Discard                           // /dev/null for io.Writer

// ── bufio ──────────────────────────────────────────────────────────────────
s := bufio.NewScanner(r)            // line-by-line scanner
s.Split(bufio.ScanWords)            // word-by-word instead
for s.Scan() { s.Text() }           // iteration pattern
w := bufio.NewWriter(f)             // buffered writer
defer w.Flush()                      // ALWAYS flush!

// ── JSON ───────────────────────────────────────────────────────────────────
json.NewEncoder(w).Encode(v)        // stream encode (HTTP/files)
json.NewDecoder(r).Decode(&v)       // stream decode (request bodies)
json.Marshal(v)                      // encode to []byte
json.Unmarshal(data, &v)            // decode from []byte

// Struct tags
`json:"name"`                        // custom key
`json:"name,omitempty"`             // skip if zero value
`json:"-"`                           // always skip (passwords, secrets)

// ── Testing ────────────────────────────────────────────────────────────────
go test -v -race ./...              // run all tests with race detector
t.Run("name", func(t *testing.T){}) // subtest
t.Parallel()                         // run subtest concurrently
t.Errorf(...)                        // non-fatal assertion failure
t.Fatalf(...)                        // fatal: stops the test
t.Helper()                           // mark as helper (fix error line reporting)
t.Cleanup(func(){})                 // cleanup after test (like defer)
```
