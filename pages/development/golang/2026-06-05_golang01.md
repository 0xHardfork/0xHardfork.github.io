# Golang

## 🧠 Concept Overview

Go's runtime is a quietly brilliant piece of engineering — a cooperative, work-stealing scheduler layered on top of OS threads, a precise garbage collector that traces pointers without stopping the world for long, and a reflection system that lets you interrogate any value at runtime without giving up type safety. Today we go behind the curtain. We will touch `reflect`, `unsafe`, understand when values escape to the heap, walk through CPU profiling with `pprof`, and learn what the Go Memory Model actually guarantees. By the end of this session you will understand *why* Go makes the performance and safety trade-offs it does.

---

### Part 1 — Reflection (`reflect` package)

Reflection in Go is the ability to inspect and manipulate variables, types, and values *at runtime*. Unlike C++ templates or Java generics, Go's approach is fully dynamic — you pay the price at runtime, not compile time.

The two central types are:

- **`reflect.Type`** — describes the *static* type of a value (its kind, fields, methods, tags…)
- **`reflect.Value`** — holds an *actual* value plus its type metadata; lets you read/write the value dynamically

#### Kinds vs Types

`reflect.Type.Kind()` returns a constant like `reflect.Struct`, `reflect.Slice`, `reflect.Ptr`, `reflect.Int64`, etc. The *kind* is the underlying primitive category. The *type* is more specific — `reflect.Type.Name()` returns `"MyStruct"`, while `Kind()` returns `reflect.Struct`.

```
Type:  MyStruct        ← user-defined name
Kind:  struct          ← underlying primitive
```

#### Getting a `reflect.Type` and `reflect.Value`

```go
var x float64 = 3.14
t := reflect.TypeOf(x)    // reflect.Type  — describes float64
v := reflect.ValueOf(x)   // reflect.Value — holds 3.14
```

`reflect.ValueOf` receives a **copy** (Go always passes by value). If you want to mutate the original, pass a pointer:

```go
p := reflect.ValueOf(&x).Elem()   // Elem() dereferences the pointer
p.SetFloat(2.71)                   // mutates x in place
fmt.Println(x)                     // 2.71
```

Calling `Set*` on a non-addressable Value panics. Rule of thumb: if you passed `&x`, you can call `.Elem()` to get an addressable Value; if you passed `x` directly, you cannot.

#### Iterating Over Struct Fields

This pattern is the foundation of JSON encoding, ORM mappers, and config loaders:

```go
type Config struct {
    Host    string `json:"host"    env:"APP_HOST"`
    Port    int    `json:"port"    env:"APP_PORT"`
    Debug   bool   `json:"debug"   env:"APP_DEBUG"`
}

func PrintFields(v any) {
    rv := reflect.ValueOf(v)
    rt := reflect.TypeOf(v)

    // Dereference pointer if needed
    if rv.Kind() == reflect.Ptr {
        rv = rv.Elem()
        rt = rt.Elem()
    }

    for i := 0; i < rt.NumField(); i++ {
        field := rt.Field(i)          // reflect.StructField
        val   := rv.Field(i)          // reflect.Value

        jsonTag := field.Tag.Get("json")
        envTag  := field.Tag.Get("env")

        fmt.Printf("Field: %-8s | JSON: %-8s | Env: %-12s | Value: %v\n",
            field.Name, jsonTag, envTag, val.Interface())
    }
}
```

#### Calling Methods Dynamically

```go
method := reflect.ValueOf(myObj).MethodByName("Process")
if method.IsValid() {
    results := method.Call([]reflect.Value{
        reflect.ValueOf("arg1"),
        reflect.ValueOf(42),
    })
    fmt.Println(results[0].Interface()) // first return value
}
```

#### Creating New Values Dynamically

```go
t := reflect.TypeOf(Config{})
newPtr := reflect.New(t)           // allocates *Config, returns reflect.Value of *Config
newPtr.Elem().FieldByName("Host").SetString("localhost")
cfg := newPtr.Interface().(*Config)
fmt.Println(cfg.Host) // "localhost"
```

#### Reflection Performance

Reflection is *slow* — typically 2–10× slower than direct calls due to interface boxing and runtime type lookups. The golden rule: use reflection in setup code (startup, schema parsing) or low-frequency paths. Never put reflection inside hot loops.

### Part 2 — The `unsafe` Package

`unsafe` punches a hole in Go's type system. It lets you:

1. Reinterpret memory (cast a pointer of type A to a pointer of type B)
2. Compute offsets of struct fields manually
3. Convert `[]byte` to `string` without copying (dangerous but fast)

The three key tools are:

| Function | Returns | Description |
|---|---|---|
| `unsafe.Sizeof(x)` | `uintptr` | Size of x in bytes (compile-time constant) |
| `unsafe.Alignof(x)` | `uintptr` | Alignment requirement in bytes |
| `unsafe.Offsetof(x.Field)` | `uintptr` | Byte offset of a struct field |
| `unsafe.Pointer(p)` | `unsafe.Pointer` | Convert any `*T` to an opaque pointer |

`uintptr` is just an integer — the GC does **not** trace it. If you store a pointer as `uintptr` and GC runs, the object can be collected and the address becomes dangling. Always convert `unsafe.Pointer` back to a real pointer type immediately without intermediate `uintptr` storage.

**Safe pattern** (GC-safe pointer arithmetic):

```go
// Advance a pointer by N bytes — safe only inside a single expression
second := (*int)(unsafe.Pointer(uintptr(unsafe.Pointer(&arr[0])) + unsafe.Sizeof(arr[0])))
```

**Zero-copy string ↔ []byte** (modern, safe way using `unsafe.SliceData` / `unsafe.StringData`, Go 1.20+):

```go
func bytesToString(b []byte) string {
    return unsafe.String(unsafe.SliceData(b), len(b))
}

func stringToBytes(s string) []byte {
    return unsafe.Slice(unsafe.StringData(s), len(s))
}
```

**Warning**: The resulting string or slice shares the same backing array. Mutating the bytes after creating the string causes undefined behavior because strings are supposed to be immutable. Use only when you are certain the original slice won't change.

### Part 3 — Escape Analysis: Stack vs Heap

When you allocate something in Go, the compiler decides whether it lives on the *goroutine's stack* (cheap — just move the stack pointer) or the *heap* (managed by the GC).

**Stack allocation** — frame is created on goroutine entry, destroyed on return. Zero GC pressure.

**Heap allocation** — the GC must find and collect the object. Each allocation is tracked.

The compiler performs *escape analysis* to determine which applies. A value "escapes to the heap" if:

- Its address is taken and stored beyond the function's lifetime
- It is assigned to an interface (the concrete value is boxed on the heap)
- It is sent over a channel
- It is too large to fit on the stack (default goroutine stack starts at 8 KB, grows dynamically)
- It is returned from a function via a pointer

**Visualize escapes** with:

```bash
go build -gcflags="-m" ./...
# or more verbose:
go build -gcflags="-m -m" ./...
```

Output example:
```
./main.go:12:6: moved to heap: x
./main.go:18:13: make([]int, n) escapes to heap
```

**Practical tips to reduce allocations**:

- Prefer `[]byte` buffers with `sync.Pool` for hot paths
- Return values by value, not pointer, when the struct is small
- Pre-size slices with `make([]T, 0, cap)` to avoid repeated copying
- Use `strings.Builder` instead of `+` concatenation in loops
- Be careful with closures — they capture variables by reference, boxing them on the heap

### Part 4 — Profiling with `pprof`

Go ships `net/http/pprof` and `runtime/pprof` out of the box. No external profiler needed.

#### Inline HTTP profiling (typical for servers)

```go
import _ "net/http/pprof"  // side-effect import registers handlers

go func() {
    log.Println(http.ListenAndServe("localhost:6060", nil))
}()
```

Then from the terminal:
```bash
# CPU profile for 30 seconds
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30

# Heap (allocation) profile
go tool pprof http://localhost:6060/debug/pprof/heap

# Goroutine dump
curl http://localhost:6060/debug/pprof/goroutine?debug=2
```

#### File-based profiling (for CLIs / tests)

```go
f, _ := os.Create("cpu.prof")
pprof.StartCPUProfile(f)
defer pprof.StopCPUProfile()

// ... your code ...

mf, _ := os.Create("mem.prof")
runtime.GC()  // force GC to get accurate snapshot
pprof.WriteHeapProfile(mf)
```

Then:
```bash
go tool pprof -http=:8080 cpu.prof   # opens a browser flame graph
```

#### Benchmark-integrated profiling

```bash
go test -bench=. -cpuprofile=cpu.prof -memprofile=mem.prof ./...
go tool pprof -http=:8080 cpu.prof
```

#### Reading a flame graph

- The X-axis shows *time* — wider bars = more CPU time
- The Y-axis shows *call depth* — the root of the call stack is at the bottom
- Look for wide bars near the top — those are the leaf functions consuming the most CPU
- `runtime.mallocgc` appearing high in the profile = too many allocations — reduce, pool, or preallocate

#### `trace` for concurrency analysis

```bash
curl http://localhost:6060/debug/pprof/trace?seconds=5 > trace.out
go tool trace trace.out
```

This gives a timeline of goroutine scheduling, GC events, and network I/O — invaluable for diagnosing goroutine starvation or scheduler latency.

### Part 5 — The Go Memory Model

The Go Memory Model (formally documented at https://go.dev/ref/mem) answers: *when is a write in goroutine A visible to goroutine B?*

The key idea is **happens-before**. If event A happens-before event B, A's writes are visible when B reads them. Without an established happens-before relationship, the compiler and CPU are free to reorder operations — meaning a write in A may never be seen by B.

#### Guaranteed synchronization events

| Event | Establishes happens-before |
|---|---|
| `go` statement | goroutine creation happens-before the goroutine's first instruction |
| Channel send | send on channel happens-before corresponding receive completes |
| Channel close | `close(ch)` happens-before receive of zero value after close |
| `sync.Mutex` Unlock | Unlock on L happens-before the next Lock on L |
| `sync.WaitGroup` Done | Done happens-before Wait returns |
| `sync/atomic` ops | Sequentially consistent atomics establish happens-before |

#### The classic data race

```go
var x int

go func() { x = 1 }()
fmt.Println(x)  // DATA RACE — no synchronization between goroutines
```

The Go race detector catches this:

```bash
go run -race main.go
go test -race ./...
```

**Always run tests with `-race`** in CI. The race detector adds ~5–10% runtime overhead in production but ~2–20× in test mode — that's fine.

#### Atomics vs Mutexes

- Use `sync/atomic` for single variables (counters, flags) — cheaper than a mutex, lock-free
- Use `sync.Mutex` / `sync.RWMutex` for protecting composite state (multiple variables that must be consistent together)
- Never roll your own lock-free algorithm without deeply understanding the memory model — use the standard library

```go
var counter int64
atomic.AddInt64(&counter, 1)       // safe
atomic.LoadInt64(&counter)         // safe

// Compare-and-swap for lock-free updates
old := atomic.LoadInt64(&counter)
atomic.CompareAndSwapInt64(&counter, old, old*2)
```

### Part 6 — The Go Scheduler (bonus deep-dive)

Go uses an **M:N** threading model: M goroutines are multiplexed on N OS threads. The scheduler has three key components:

- **G** — goroutine (user-level thread with its own stack)
- **M** — OS thread (machine)
- **P** — processor (holds a run queue; M must hold a P to run Gs)

The `GOMAXPROCS` environment variable (default: number of CPU cores) sets how many Ps exist. Each P has a local run queue of Gs. When a G blocks on I/O, its M releases the P so another M can pick up the P and keep running Gs. This is why thousands of goroutines can coexist on a handful of OS threads.

The scheduler is **cooperative-preemptive**: goroutines yield at function calls (historically cooperative) and also at async safe points inserted by the compiler (preemptive since Go 1.14). This means tight loops no longer starve other goroutines.

**`runtime.Gosched()`** manually yields the current goroutine, giving the scheduler a chance to run others. Use sparingly — it's a hint, not a guarantee.

**`runtime.NumGoroutine()`** returns the current goroutine count — useful in tests and dashboards to detect goroutine leaks.

## 🔑 Key Points

- `reflect.TypeOf` / `reflect.ValueOf` are your entry points; use `.Elem()` to dereference pointers and enable mutation via `Set*`
- `unsafe.Pointer` is legal; `uintptr` is dangerous — never store an address as `uintptr` across a GC point
- Escape analysis determines stack vs heap; inspect with `go build -gcflags="-m"`; reduce heap allocs in hot paths
- `net/http/pprof` gives CPU, heap, goroutine, and trace profiles with zero setup on running servers
- The Go Memory Model requires explicit synchronization (channels, mutexes, atomics) — the compiler and CPU will reorder unsynchronized accesses
- Go's M:N scheduler multiplexes goroutines on OS threads via G/M/P; `GOMAXPROCS` controls parallelism
- Always run `go test -race ./...` in CI — the race detector catches concurrency bugs that intermittently fail in prod

### Example 1 — Generic Pretty-Printer via Reflection

```go
// File: reflect_printer.go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

// PrettyPrint recursively prints any value with type information.
func PrettyPrint(v any, indent int) {
	prefix := strings.Repeat("  ", indent)
	rv := reflect.ValueOf(v)

	// Dereference pointer
	for rv.Kind() == reflect.Ptr {
		if rv.IsNil() {
			fmt.Printf("%s<nil ptr>\n", prefix)
			return
		}
		rv = rv.Elem()
	}

	rt := rv.Type()

	switch rv.Kind() {
	case reflect.Struct:
		fmt.Printf("%s%s {\n", prefix, rt.Name())
		for i := 0; i < rt.NumField(); i++ {
			field := rt.Field(i)
			if !field.IsExported() {
				continue
			}
			fmt.Printf("%s  .%s:", prefix, field.Name)
			val := rv.Field(i)
			if val.Kind() == reflect.Struct || val.Kind() == reflect.Ptr {
				fmt.Println()
				PrettyPrint(val.Interface(), indent+2)
			} else {
				fmt.Printf(" %v (%s)\n", val.Interface(), val.Type())
			}
		}
		fmt.Printf("%s}\n", prefix)

	case reflect.Slice, reflect.Array:
		fmt.Printf("%s[%d]%s [\n", prefix, rv.Len(), rt.Elem())
		for i := 0; i < rv.Len(); i++ {
			PrettyPrint(rv.Index(i).Interface(), indent+1)
		}
		fmt.Printf("%s]\n", prefix)

	case reflect.Map:
		fmt.Printf("%smap[%s]%s {\n", prefix, rt.Key(), rt.Elem())
		for _, key := range rv.MapKeys() {
			fmt.Printf("%s  [%v]:\n", prefix, key)
			PrettyPrint(rv.MapIndex(key).Interface(), indent+2)
		}
		fmt.Printf("%s}\n", prefix)

	default:
		fmt.Printf("%s%v (%s)\n", prefix, rv.Interface(), rv.Type())
	}
}

type Address struct {
	Street string
	City   string
}

type Person struct {
	Name    string
	Age     int
	Tags    []string
	Address Address
}

func main() {
	p := Person{
		Name: "Alice",
		Age:  30,
		Tags: []string{"gopher", "hacker"},
		Address: Address{
			Street: "1 Infinite Loop",
			City:   "Cupertino",
		},
	}
	PrettyPrint(p, 0)
}
```

**What this demonstrates**: Recursive structural introspection using `reflect.Kind` switching — the same pattern used inside `encoding/json`, `fmt`, and `database/sql` drivers.

### Example 2 — Escape Analysis Benchmark: Stack vs Heap

```go
// File: escape_bench_test.go
package main

import (
	"fmt"
	"testing"
)

// stackAlloc returns a value — compiler keeps it on stack (no escape)
func stackAlloc() [4]int {
	return [4]int{1, 2, 3, 4}
}

// heapAlloc returns a pointer — value must outlive the function, escapes to heap
func heapAlloc() *[4]int {
	arr := [4]int{1, 2, 3, 4}
	return &arr // &arr escapes
}

// interfaceEscape boxes the int into an interface{} — causes heap allocation
func interfaceEscape(n int) any {
	return n // n is boxed: heap allocation
}

func BenchmarkStack(b *testing.B) {
	var sink [4]int
	for i := 0; i < b.N; i++ {
		sink = stackAlloc()
	}
	_ = sink
}

func BenchmarkHeap(b *testing.B) {
	var sink *[4]int
	for i := 0; i < b.N; i++ {
		sink = heapAlloc()
	}
	_ = sink
}

func BenchmarkInterfaceBox(b *testing.B) {
	var sink any
	for i := 0; i < b.N; i++ {
		sink = interfaceEscape(i)
	}
	_ = sink
}

func main() {
	fmt.Println("Run with: go test -bench=. -gcflags='-m' .")
}
```

**What this demonstrates**: The cost difference between stack and heap allocation — `BenchmarkHeap` will show significantly more `allocs/op` than `BenchmarkStack`. The `-gcflags='-m'` flag prints which values escape.

### Example 3 — CPU Profiling a Real Workload

```go
// File: profile_demo.go
package main

import (
	"fmt"
	"math"
	"os"
	"runtime/pprof"
)

// expensiveWork simulates CPU-intensive processing.
func expensiveWork(n int) float64 {
	sum := 0.0
	for i := 0; i < n; i++ {
		sum += math.Sqrt(float64(i)) * math.Log(float64(i+1))
	}
	return sum
}

// matMul multiplies two n×n matrices — classic O(n³) benchmark.
func matMul(a, b [][]float64, n int) [][]float64 {
	c := make([][]float64, n)
	for i := range c {
		c[i] = make([]float64, n)
	}
	for i := 0; i < n; i++ {
		for k := 0; k < n; k++ {
			for j := 0; j < n; j++ {
				c[i][j] += a[i][k] * b[k][j]
			}
		}
	}
	return c
}

func main() {
	// Start CPU profiling
	cpuFile, err := os.Create("cpu.prof")
	if err != nil {
		panic(err)
	}
	defer cpuFile.Close()
	pprof.StartCPUProfile(cpuFile)
	defer pprof.StopCPUProfile()

	// Workload 1: math-heavy loop
	result := expensiveWork(5_000_000)
	fmt.Printf("expensiveWork result: %.4f\n", result)

	// Workload 2: matrix multiplication
	n := 200
	a := make([][]float64, n)
	b := make([][]float64, n)
	for i := range a {
		a[i] = make([]float64, n)
		b[i] = make([]float64, n)
		for j := range a[i] {
			a[i][j] = float64(i + j)
			b[i][j] = float64(i * j)
		}
	}
	c := matMul(a, b, n)
	fmt.Printf("matMul[0][0] = %.2f\n", c[0][0])

	fmt.Println("Profile written to cpu.prof")
	fmt.Println("Analyze with: go tool pprof -http=:8080 cpu.prof")
}
```

**What this demonstrates**: How to instrument production-like code with `pprof` CPU profiling, then analyze the flame graph to find bottlenecks.

### Example 4 — `unsafe` Zero-Copy String/Byte Conversion + Struct Field Hacking

```go
// File: unsafe_demo.go
package main

import (
	"fmt"
	"unsafe"
)

// --- Zero-copy string <-> []byte (Go 1.20+) ---

func bytesToStringUnsafe(b []byte) string {
	if len(b) == 0 {
		return ""
	}
	return unsafe.String(unsafe.SliceData(b), len(b))
}

func stringToBytesUnsafe(s string) []byte {
	if len(s) == 0 {
		return nil
	}
	return unsafe.Slice(unsafe.StringData(s), len(s))
}

// --- Struct layout inspection ---

type Point struct {
	X int32
	Y int32
	Z int64
}

func printLayout() {
	var p Point
	fmt.Printf("Point size:       %d bytes\n", unsafe.Sizeof(p))
	fmt.Printf("Point alignment:  %d bytes\n", unsafe.Alignof(p))
	fmt.Printf("Offset of X:      %d bytes\n", unsafe.Offsetof(p.X))
	fmt.Printf("Offset of Y:      %d bytes\n", unsafe.Offsetof(p.Y))
	fmt.Printf("Offset of Z:      %d bytes\n", unsafe.Offsetof(p.Z))
	// Z is int64 — needs 8-byte alignment, so 4 bytes of padding after Y
}

// --- Mutate an unexported field via unsafe (educational only — don't do this in prod) ---

type secretBox struct {
	hidden int // unexported — normally inaccessible from outside package
	Public string
}

func peekSecret(b *secretBox) int {
	// Walk to the first field's address
	return *(*int)(unsafe.Pointer(b))
}

func main() {
	// Zero-copy conversion
	original := []byte("Hello, Gopher!")
	s := bytesToStringUnsafe(original)
	fmt.Printf("bytesToString (no alloc): %q\n", s)

	back := stringToBytesUnsafe(s)
	fmt.Printf("stringToBytes (no alloc): %v\n", back[:5])

	fmt.Println()
	printLayout()

	fmt.Println()
	box := &secretBox{hidden: 42, Public: "visible"}
	fmt.Printf("Peeked hidden field via unsafe: %d\n", peekSecret(box))
}
```

**What this demonstrates**: Practical `unsafe` use cases — zero-copy type conversions, struct memory layout inspection, and a cautionary example of accessing unexported fields (only for educational purposes — it breaks in different Go versions).

### Example 5 — Race Detector Demo + Atomic Fix

```go
// File: race_demo.go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

// BAD: data race — run with -race to catch it
func racyCounter() {
	var count int
	var wg sync.WaitGroup

	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			count++ // RACE: concurrent unsynchronized write
		}()
	}
	wg.Wait()
	fmt.Printf("Raced count (undefined): %d\n", count)
}

// GOOD: atomic counter — no race
func atomicCounter() int64 {
	var count int64
	var wg sync.WaitGroup

	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			atomic.AddInt64(&count, 1) // safe: atomic RMW operation
		}()
	}
	wg.Wait()
	return count
}

// GOOD: mutex-protected composite state
type SafeState struct {
	mu    sync.Mutex
	count int
	sum   int64
}

func (s *SafeState) Add(n int) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.count++
	s.sum += int64(n)
}

func (s *SafeState) Stats() (int, int64) {
	s.mu.Lock()
	defer s.mu.Unlock()
	return s.count, s.sum
}

func main() {
	// Uncomment to see the race detector fire:
	// racyCounter()

	c := atomicCounter()
	fmt.Printf("Atomic count: %d (should be 1000)\n", c)

	state := &SafeState{}
	var wg sync.WaitGroup
	for i := 1; i <= 100; i++ {
		i := i
		wg.Add(1)
		go func() {
			defer wg.Done()
			state.Add(i)
		}()
	}
	wg.Wait()

	count, sum := state.Stats()
	fmt.Printf("Mutex state: count=%d, sum=%d (should be 100, 5050)\n", count, sum)
}
```

**What this demonstrates**: The classic data race pattern vs. two correct fixes — `sync/atomic` for single variables and `sync.Mutex` for composite state.

## ⚠️ Common Mistakes

| Mistake | Why it's wrong | Correct approach |
|---------|---------------|-----------------|
| Calling `reflect.Value.Set*` on a non-addressable value | Panics at runtime; direct `reflect.ValueOf(x)` creates a copy, not addressable | Pass a pointer: `reflect.ValueOf(&x).Elem()` |
| Storing an `unsafe.Pointer` as `uintptr` across statements | The GC may collect the object between statements, leaving a dangling `uintptr` | Keep as `unsafe.Pointer` until the last moment; do arithmetic in one expression |
| Assuming goroutine writes are visible without synchronization | The Go Memory Model makes no guarantee without happens-before via channel/mutex/atomic | Always use channels, mutexes, or `sync/atomic` to share state |
| Not running `go test -race` in CI | Data races are non-deterministic; they may only surface under load or on certain CPUs | Add `-race` to all test commands in your CI pipeline |
| Using reflection in tight loops for "convenience" | 2–20× slower than direct calls; causes extra allocations and GC pressure | Use reflection only in setup/initialization code; generate code or use generics for hot paths |
| Forgetting `runtime.GC()` before heap profiling | The heap profile may show stale, not-yet-collected objects, giving misleading data | Always call `runtime.GC()` just before `pprof.WriteHeapProfile()` |

### Exercise 1 — Struct Tag Parser (Easy)

**Goal**: Write a function `ParseTags(v any) map[string]map[string]string` that uses reflection to extract all struct tags from a given struct value, returning a map of `fieldName → tagKey → tagValue`.

**Requirements**:
- Accept any struct (or pointer to struct) as `any`
- Return a nested map: outer key is the field name, inner key is the tag name (e.g., `"json"`, `"env"`), inner value is the tag value
- Handle pointer-to-struct transparently
- Skip unexported fields

**Starter code**:

```go

import (
	"fmt"

	// TODO: Use reflect.TypeOf, NumField, Field(i).Tag.Lookup or Tag.Get

type Server struct {
```

### Exercise 6 — Memory Model: Fix the Races (Medium)

**Goal**: The following program has 3 distinct data races. Find them using `-race`, fix each one using the appropriate synchronization primitive, and explain why you chose that primitive.

**Requirements**:
- Fix Race 1 using `sync/atomic`
- Fix Race 2 using `sync.RWMutex`
- Fix Race 3 using a channel
- Add a comment next to each fix explaining the happens-before relationship established

**Starter code**:

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

// Race 1: shared counter
var globalCounter int

func incrementRacy(wg *sync.WaitGroup) {
	defer wg.Done()
	globalCounter++ // RACE
}

// Race 2: shared cache
var cache = map[string]string{}

func writeCache(key, val string) {
	cache[key] = val // RACE
}

func readCache(key string) string {
	return cache[key] // RACE
}

// Race 3: signal from goroutine
var done bool

func worker() {
	time.Sleep(10 * time.Millisecond)
	done = true // RACE
}

func main() {
	var wg sync.WaitGroup
	for i := 0; i < 100; i++ {
		wg.Add(1)
		go incrementRacy(&wg)
	}
	wg.Wait()
	fmt.Println("Counter:", globalCounter)

	go writeCache("foo", "bar")
	time.Sleep(1 * time.Millisecond)
	fmt.Println("Cache:", readCache("foo"))

	go worker()
	for !done { // RACE
		time.Sleep(1 * time.Millisecond)
	}
	fmt.Println("Done!")
}
```

**Hint**: For Race 3, a `chan struct{}` with `close(doneCh)` is idiomatic Go — closing a channel establishes happens-before for all receivers.
